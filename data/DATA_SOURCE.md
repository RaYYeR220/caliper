# Data sources and provenance

Everything under `data/` is a **frozen fixture** committed for reproducibility. Nothing here
is a live feed, and nothing here is refreshed automatically. Two scripts regenerate the tree:

- `scripts/fetch_trials.py` -- trial snapshots
- `scripts/build_patient_corpus.py` -- patient corpus

`data/SHA256SUMS` lists a SHA-256 digest for every other file under `data/`, and
`tests/test_data_integrity.py` verifies them.

All files are written in one canonical form: UTF-8, two-space indent, object keys sorted,
LF newlines, one trailing newline. Byte layout is therefore identical on every platform.

### Modifications

**None to content.** Each file is the complete, unabridged response body for one study,
with every field the API returned. The only change is serialisation: the JSON was
re-formatted into the canonical layout described above (pretty-printed, object keys sorted
alphabetically). No field was added, removed, renamed, reordered within an array, or
altered in value. Ordering of JSON object keys is not semantically significant.

### Status of this copy

This is a point-in-time snapshot taken for a demonstration, **not a mirror and not a
continuously updated copy**. ClinicalTrials.gov is the authoritative source and its records
change; these files will drift out of date and are not maintained. Anyone needing current
data must query ClinicalTrials.gov directly. No proprietary rights are asserted over this
data by this project or its authors.

The upstream `downloads/latest/` path is **mutable** -- it is overwritten whenever the sample
data is regenerated. The build therefore resolves the newest commit touching that path via
the GitHub API and downloads through the immutable
`raw.githubusercontent.com/synthetichealth/synthea-sample-data/{SHA}/...` URL, then verifies
the archive digest before reading it. `data/patients/PROVENANCE.json` carries the same
values in machine-readable form.

### No PHI

**Every patient record here is synthetic.** The bundles were generated by Synthea, a
simulator; they describe people who do not exist. There is no protected health information,
no de-identified real patient data, and no re-identification risk. Names, addresses and
identifiers are all fabricated by the generator.

### Modifications

Two modifications were made and both are declared here.

**a. Resource types removed.** Each bundle was trimmed to the resource types the screening
engine can reason over. Entries whose `resource.resourceType` was **not** one of

> `AllergyIntolerance`, `Condition`, `DocumentReference`, `Encounter`, `Immunization`,
> `MedicationRequest`, `Observation`, `Patient`, `Procedure`

were removed in full. Across the 24 committed bundles this removed **4,278 of 14,141 entries
(64.8% of bytes)**, comprising exactly these resource types:

| Removed resource type | Entries removed |
|---|---|
| CarePlan | 56 |
| CareTeam | 56 |
| Claim | 1,005 |
| Device | 83 |
| DiagnosticReport | 1,393 |
| ExplanationOfBenefit | 1,005 |
| ImagingStudy | 65 |
| Medication | 114 |
| MedicationAdministration | 114 |
| Provenance | 24 |
| SupplyDelivery | 363 |

Consequence to be aware of: retained resources are unchanged in content, but references
from them to removed resources (an `Encounter` naming its `Organization`, a
`MedicationRequest` naming its `Medication`) are still present and **no longer resolvable
within this corpus**. The bundles are therefore not self-contained FHIR transactions.

**b. Re-serialised** into the canonical layout described at the top of this file. No
retained resource had any field added, removed or altered.

The bundles are otherwise complete: bundle-level fields and every retained entry are
byte-equivalent in content to the upstream archive.

### Selection

24 patients were selected from the 109 candidate bundles in the archive. Selection is
deterministic and is re-derived by the build script; `PROVENANCE.json` records the reason
each patient was admitted.

Patients were scored out of ten on evidence a screener needs: adult age (18-85 as of the
fixed reference date **2026-06-01**), presence of a diabetes / CKD / heart-failure / COPD /
asthma `Condition`, and Observations for each of eight laboratory and vital-sign codes
(creatinine, HbA1c, eGFR, glucose, BMI, systolic BP, haemoglobin, platelets).

Selection is a budgeted covering problem, not a top-N cut. Synthea records grow with the
length of the simulated life, so the patients carrying the most evidence are also the
largest. Capacity is reserved, in order, for the dimensions the screener must be able to
exercise, and only the remainder is spent on the best evidence-per-byte candidates:

| Reserved for | Quota | Carriers in the final corpus |
|---|---|---|
| Deliberately sparse patients | 5 | 5 |
| Chronic kidney disease carriers | 1 | 1 |
| Heart failure carriers | 2 | 2 |
| COPD carriers | 2 | **1 (quota unmet)** |
| Asthma carriers | 1 | 1 |
| Diabetes carriers | 1 | 11 |
| Aged 55+ with a 20-year-plus record | 3 | 3 |
| Creatinine carriers | 4 | 13 |
| HbA1c carriers | 4 | 13 |
| eGFR carriers | 2 | 5 |
| Glucose carriers | 2 | 3 |

The right-hand column counts every patient in the corpus carrying that evidence, including
those admitted by the evidence-per-byte fill; it exceeds the quota wherever the fill
happened to bring more in.

Heart failure and COPD are held at two carriers apiece so that one patient dropping out of
a future reshuffle cannot silently remove a whole trial's worth of cases. No single patient
may be admitted as a quota anchor if it would consume more than 25% of the corpus budget,
which keeps the 10-25 MB outliers out.

The sparse quota is intentional. Cases where the correct answer is **"unknown"** because the
evidence is absent matter as much as clean ones; a screener that cannot distinguish "does
not meet the criterion" from "we do not know" is not safe. The corpus therefore includes
paediatric patients, a patient whose records stop in 1961, and a neonate with two
encounters.

### Known gaps

- **Only one COPD patient, where two were wanted.** The sample archive contains exactly one
  COPD carrier in total -- a single `Pulmonary emphysema (disorder)`; no bundle in the
  dataset carries a chronic obstructive pulmonary disease code at all. The quota cannot be
  met from this source and is recorded as `unmet_quotas` in `PROVENANCE.json`. Any trial
  keyed on COPD therefore rests on that one patient.
- Heart failure is likewise near the floor: the archive holds exactly two carriers
  (`Chronic congestive heart failure`) and both are included, so the quota is met with no
  margin.
- LOINC **777-3** is the platelet code Synthea emits, and it is the code the screening panel
  scores on; 777-7 does not occur anywhere in the archive and is retained only as an
  accepted alias.
- Panel codes are matched at both the Observation level and the component level, for every
  dimension. Synthea publishes systolic blood pressure (8480-6) only as a component of the
  85354-9 panel, so a top-level-only scan would report it as absent in all 109 patients.

## 3. Size

Total committed `data/` tree: **approximately 24.4 MB** -- 4,194,679 bytes of trial snapshots
and 20,123,512 bytes of patient bundles, plus the manifest, provenance and checksum files.
The trial files are stored whole, including the results sections of completed studies, which is why
they are not smaller.
